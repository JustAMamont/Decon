## S0 — Скелет проекта

**Цель:** репозиторий, который проходит CI с пустыми (но честными) крейтами.

Состав:
- Cargo workspace: `decon-core`, `decon-trainers`, `decon-app` (структура —
  ARCHITECTURE.md §2);
- CI (GitHub Actions): матрица ubuntu-latest + windows-latest; `cargo fmt
  --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test
  --workspace`, smoke-бенчи criterion, gitleaks;
- LICENSE (MIT), .gitignore, этот комплект документов в `docs/`;
- `rust-toolchain.toml` — зафиксированная версия toolchain.

**Критерии приёмки:**
1. Зелёный CI на обоих таргетах.
2. `cargo doc --workspace` без предупреждений (включая `#![deny(missing_docs)]`
   на публичных item).
3. gitleaks-скан в CI включён и проходит.
4. `decon-app` запускается и показывает пустое окно на обеих платформах.

## S1 — Core: модель + БД + журнал сессий

**Цель:** полноценный журнал сессий с pre/post замерами и event-логом, без
тренажёров и зондов.

Состав:
- `model/`: session, scale, event, context, settings (DDL — SPEC-data-model.md);
- `db/`: подключение (WAL, foreign_keys, synchronous=NORMAL), миграции v1
  с тестами up/down, репозитории;
- `db/crypto.rs`: fernet-обёртка, argon2id, keyring-интеграция; автоматический
  и парольный режимы (ARCHITECTURE.md §6);
- `app/views/journal/`: запуск сессии (выбор техники/слоя, контекст),
  pre-замер, экран сессии (таймер, равномерные сигналы, кнопки-маркеры),
  post-замер, история сессий;
- таймер равномерных сигналов: интервалы из настроек, звук — не резкий колокол
  (медленный нарастающий/затухающий тон).

**Критерии приёмки:**
1. Интеграционный тест: полный цикл сессии (create → pre → events → post →
   read) с roundtrip всех полей, включая зашифрованную заметку.
2. Миграции: тест up → down → up на пустой и заполненной базе.
3. Бенчмарк: append события — 0 аллокаций (подтверждено подсчётом аллокаций
   в бенче), p95 < 1 мкс без учёта I/O SQLite.
4. Тест шифрования: зашифрованная заметка не находится в файле БД поиском
   по подстроке (grep по файлу в тесте).
5. Ноль конфиг-файлов: интеграционный тест запускает приложение дважды и
   проверяет, что в домашнем каталоге не появилось ничего, кроме БД в
   XDG-каталоге данных.

## S2 — Шкалы + зонды дня

**Цель:** конструктор шкал, дефолтный набор v1 «Baseline-2026» (SCALES.md),
зонды дня с догоняющим режимом, FFMQ-15 как внешний инструмент.

Состав:
- `model/scale.rs`: версии шкал, активация/деактивация, конструктор в UI;
- `schedule/probe_scheduler.rs`: окно активности, N зондов, мин. интервал,
  паузы; детерминизм по сиду;
- `app/views/`: экраны зондов (2 слайдера + флаг), догоняющий список,
  подключение FFMQ-файла (5 факторных баллов на вход), слойная карта
  (раз в 2–4 недели);
- уведомления ОС (notify-rust / tauri-winrt-notification — по платформе).

**Критерии приёмки:**
1. Property-based тест (proptest) планировщика: 1000 случайных конфигураций —
   все зонды в окне, интервалы ≥ минимума, количество точно N.
2. Тест версионирования: изменение формулировки → старая версия читаема,
   тренды не смешиваются (запрос тренда по version_id).
3. Интеграционный тест догоняющего зонда: `delay_minutes` проставляется.
4. Pre/post пары `pre.openness` и `probe.openness` дают один ряд в аналитическом
   запросе (одинаковый scale_id — тест на SQL-уровне).

## S3 — Тренажёры: Шульте + MOT

**Цель:** два тренажёра-измерительных прибора, пишущих в общий журнал.

Состав:
- `trainers/schulte.rs`: сетка 3×3…10×10, символы (цифры/буквы/двуцветные),
  3 режима — классика / поле (фиксация в центре, поиск периферией) / дКВ
  (расфокус); метрики: время, ошибки, конфигурация;
- `trainers/mot.rs`: N целей среди distractors, фаза индикации → фаза
  движения → фаза ответа; конфиги: число целей, скорость, длительность;
  метрики: % корректных, латентность ответа;
- `trainers/rng.rs`: сидированный RNG — повторяемость прогона для тестов;
- `app/views/trainers/`: экраны тренажёров, результаты в журнал
  (`session.kind = 'trainer'`).

**Критерии приёмки:**
1. Бенчмарк MOT-тика: 0 аллокаций на тик при N ≤ 32, p95 тика < 100 мкс
   (запас к 60 Гц).
2. Детерминизм: один сид → идентичный прогон (побайтовое сравнение лога
   событий) — тест.
3. Интеграционный тест: результат тренажёра читается общим журналом вместе
   с сессиями практики.
4. UX-тест (интеграционный, headless): сценарий «пользователь прошёл
   Шульте 5×5 без ошибок» даёт время в допустимом диапазоне и ноль ошибок
   в логе.

## S4 — Аналитика + экспорт

**Цель:** тренды, корреляции, n-of-1 сравнения, экспорт.

Состав:
- `analysis/trends.rs`: скользящие средние по шкалам, раздельно по слоям и
  версиям шкал, вертикальные линии «смена инструмента»;
- `analysis/correlation.rs`: условия (сон, кофеин, время суток) ↔ качество
  (Спирмен для порядковых шкал); вывод без каузальной риторики;
- `analysis/delta.rs`: pre/post дельты, carryover-кривая по зондам;
- `analysis/n_of_1.rs`: сравнение периодов A/B (baseline ↔ вмешательство),
  оценка видимой значимости (перmutation-тест), предупреждение о малых выборках;
- `analysis/export.rs`: CSV/JSON, заметки — только по явному запросу;
- `app/views/analytics/`: дашборд, графики (своя отрисовка на SVG/canvas
  через Dioxus, без web-зависимостей).

**Критерии приёмки:**
1. Property-based тесты математики: корреляция/тренды на синтетических рядах
   с известным ответом (монотонный ряд → r ≈ 1; шум с сидом → воспроизводимость).
2. Бенчмарк: холодный проход корреляций по 10k сессий < 50 мс, без
   промежуточных аллокаций (подтверждение подсчётом).
3. Интеграционный тест экспорта: roundtrip JSON → импорт → сравнение.
4. Трезвость аналитики: при n < 30 в периоде сравнение A/B выводит явное
   предупреждение «мало данных» (тест на UI-состоянии).

## S5 — Дополнительные тренажёры

**Цель:** UFOV, звуковое поле, layer-switch drill.

Состав: `trainers/ufov.rs` (краткая вспышка периферических стимулов → отчёт),
`trainers/audio_field.rs` (пространственные источники, редкие целевые события;
rodio/CPAL), `trainers/layer_switch.rs` (случайный сигнал → переключение
фокус/поле/фон; лог времени реакции).

**Критерии приёмки:**
1. Каждый тренажёр: детерминизм по сиду + бенчмарк тика (0 аллокаций).
2. Звуковое поле: кросс-платформенный вывод (Linux + Windows) — интеграционный
   тест с виртуальным аудиовыходом.
3. Layer-switch: лог времени реакции пишется в trainer_log, тест диапазонов.

## S6 — Android-порт

**Цель:** APK с теми же core/trainers, фоновой доставкой зондов.

Условия старта: десктоп стабилен ≥ 1 месяц ежедневного использования;
Dioxus mobile проверен на актуальность прототипом-спайком.

Состав: платформенный слой уведомлений через системный планировщик
(work-manager-аналог), сборка APK через CI (добавить android-джобу).

**Критерии приёмки:** зонды приходят при свёрнутом приложении (ручная
проверка на устройстве, чек-лист в PR); сборка APK в CI зелёная.

## S7 — Веб-сервис сообщества

**Цель:** опциональная синхронизация и сообщество; локальный режим остаётся
полноценным навсегда.

Состав: сервер на axum с `decon-core` как доменный слой; sync-протокол
(UUID v7 + updated_at + soft-delete уже в модели с S1); аутентификация,
шифрование на сервере (нулевое доверие: сервер не видит заметки — fernet-ключ
у клиента); UI — Dioxus web-таргет из того же кодбазиса.

**Критерии приёмки:** conflict resolution протестирован на симуляции
двух устройств; локальный режим без аккаунта продолжает работать после
установки обновления (регрессионный тест).
